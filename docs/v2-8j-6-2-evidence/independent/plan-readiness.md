## Findings resolved in the revised contract

1. **Metadata resource admission.** Inspect validates the full saved document/catalog even though it produces no native file. POST-only admission left that new path outside the family bound. Final contract shares at most two active family operations per process and one per owner between GET and POST, releases only after actual work settles, and holds no slot during human confirmation. Disconnect is not represented as stopping an already-running library call.
2. **Uncited size compatibility.** A shared controller could silently apply the new notes-only64MiB cap to accepted uncited downloads. Final contract explicitly limits the new server/browser cap to notes POST and retains legacy uncited size behavior. It makes no claim that the legacy path gains these resource bounds.
3. **Bounded metadata/error parsing.** A bounded server response is insufficient reason to consume arbitrary client responses with res.json(). Final contract caps actual UTF-8 metadata/error bytes at8KiB independent of Content-Length, requires JSON MIME, validates exact metadata/project identity/safe counters/citationCount0–512 before a modal, and compares the displayed revision. Errors use a static allowlist. Redirects refuse; captured requests use no-store and credentials:omit.
4. **Middleware ordering.** `app/server/index.js:55` installs potentially short-circuiting CORS before existing private parsers. Final contract puts the family's raw-path private-header boundary before CORS/parser short circuits and retains a scoped late static-error boundary for case variants, malformed parameter decoding and unknown paths/methods. Existing CORS OPTIONS is explicitly permitted only as non-disclosing preflight metadata with private headers, no authentication/project/source/body/generation work and no CORS widening.
5. **Competing component instances.** Separate card/topbar/Projects instances could each acquire a local ref and open competing confirmation/focus traps. Final contract requires one synchronously claimed active saved-export flow per mounted Workspace/SceneViewer scope, rejects other starts while active, and allows only the owning ticket to release it. Cancel may free the UI while the independent server slot remains occupied until work settles.

All five are resolved at `063e46d2e78d26b40445558ca0dc42e09aa30daa`. No unresolved technical contract issue remains.
