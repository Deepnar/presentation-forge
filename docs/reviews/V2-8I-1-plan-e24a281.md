## Scope and authority

The selected five operations are a coherent first transport dependency. H already
owns bounded visible views, exact input identities, expiry/replay, cancellation,
clear and atomic canonical enqueue. The transport can expose those operations
without introducing public submit/prepare/claim/advance, worker lifetime, provider
configuration or a competing document/queue. Preparing records through trusted
host/CLI entry points and then exercising actual HTTP decisions is useful complete
behavior within this scope; it does not claim a usable Assistant surface yet.

The current `resolveProjectOwner` can supply the authenticated owner, but its admin
flag must be discarded. Both real `withRuntimeTransaction` implementations enforce
project access with `admin=false`, supporting the proposed cross-owner 404 policy.
The existing browser project client uses bearer session headers. The existing
cookie path remains `/api/decks`; this slice makes no cookie-only browser-session
promise and needs no cookie/auth-policy expansion.

One ambiguity was identified and corrected during review. Original plan wording
said H rechecks "revocation and ownership". H receives an owner/project binding
and rechecks project ownership under its lock; it does not revalidate session
tokens. The inspected clarification now explicitly distinguishes current-project
access revocation from session/logout revocation, which takes effect on the next
HTTP request under existing policy. No atomic in-flight logout/commit fence is
claimed. Required tests will include next-request logout 401 and actual project
ownership/deletion/revision changes. No unresolved policy blocker remains.

## Conditions to preserve during implementation

- Install the private/no-store prefix behavior and bounded parser/error handling
  before the existing global 8 MiB parser. Cover malformed/oversize JSON, GET bodies,
  non-JSON mutations and unknown execution paths using the real production server.
  Do not let Express's default parser response or the existing generic `wrap`
  expose request bytes or raw exception messages on this prefix.
- Construct only the owner/project binding from trusted resolution. Keep mutation
  bodies exact and pass their original generation/revision/decision identity to H;
  never infer the current generation, replace a stale revision or accept supplied
  edits, run IDs, owner/admin fields or provider configuration as authority.
- Preserve H's return/refusal semantics and allowlist error/status mapping,
  including final approval-expiry fencing, conflicting replay and storage failures.
  Sanitization must apply to authorization/service-factory failures as well as
  domain failures. A response loss or disconnected client must leave a committed
  decision replayable with the same canonical run identity.
- Keep pagination parsing strict for repeated/unknown/bracketed/invalid decimal
  query values. Validate the project ID before deriving an attachment filename.
  Export only H's bounded visible view; its linked run view deliberately omits
  private plans, receipt payloads and provider/context material.
- Exercise real SQLite and PostgreSQL plus production Express wiring, with offline
  trusted preparation and canonical runtime execution. Preserve the HTTP/domain/CLI
  equivalence, ownership/delete/human-save races, clear/history/accounting and absent
  execution-route assertions. Controlled faults may isolate safe error mapping;
  they must not replace real auth/storage lifecycle tests.
